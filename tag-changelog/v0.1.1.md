# v0.1.1

First release. Workspace: `racking-server`, `rack`, `racking-mcp`; Rust 2024, `rust-version = "1.88"`, `unsafe_code = "forbid"`.

## racking-server
- HTTP/JSON over `tiny_http` (blocking, thread per request, max 64 in flight), SQLite via bundled `rusqlite`; `--config FILE` (bind default `127.0.0.1:7878`, `data_dir`, `[agents.NAME] token, admin`); refuses tokens under 24 chars or containing `CHANGE-ME`.
- Auth: Bearer only, tokens kept as sha256 and compared in constant time (`api.rs`); `from` always comes from the token.
- Job kinds (`types.rs`, `store.rs`): `task` (states sent/received/accepted/done/failed/rejected), `comment`, `result`, `notice` (<= 1 KiB, no files), `message` (<= 64 KiB, files, title from first line <= 80 chars), `report` (<= 1 MiB, title required). `priority` low|normal|high, `expects_reply`, `body_truncated`.
- Inbox/outbox: `seq` and `updated_seq` cursors; `/inbox/wait` and `/outbox/wait` (default 25 s, max 55 s, Condvar, no polling); notices and messages <= 4 KiB come inline, the rest as 200-char previews; notices/messages/reports move to `received` on delivery and to `answered` on a reply.
- Attachments: 64 MiB per file, 256 MiB and 16 files per job, `X-Sha256` checked, uploads only while `sent`.
- Idempotency-Key per agent, 24 h; error shape `{error:{code,message,hint}}`; `GET /` and `GET /help` generated from the route table.
- `dist.rs`: `GET /dist/manifest`, `GET|PUT /dist/{target}/{file}`; publish needs `admin = true`; target allowlist x86_64-unknown-linux-gnu, x86_64-pc-windows-gnu, aarch64-unknown-linux-gnu; 32 MiB; latest per target.
- `presence.rs`: `GET /agents`, `PUT /agents/me`; `online` = activity within 90 s or inside a wait; `last_seen` in memory, written at most once a minute; version and OS from `X-Rack-Version` and `X-Rack-Os` headers.
- Retention: closed and delivered jobs purged after 30 days.

## rack
- `send`, `say`, `notify`, `report`, `ask` (default 60 s, `--resume`), `inbox`, `wait`, `show`, `accept`, `reject`, `result`, `attach`, `get-attachment`, `outbox`, `agents`, `about`, `pull`, `update`, `publish`, `version`/`--version`/`-V`.
- `pull` creates kb entries only through the `kb` CLI (`--` before titles), links saved in `state.json`; notices and messages are only printed; `--notes` makes a kb note per report.
- `update`: version from the server manifest, sha256 and size checked, new binary run with `--version` before replacing; Unix rename, Windows `rack.old`; origin isolated in `update/origin.rs`.
- Config: `RACK_URL`/`RACK_TOKEN` or `RACK_CONFIG` file.

## racking-mcp
- MCP revision 2025-11-25 over stdio, hand-written JSON-RPC; 16 tools: `racking_` whoami, agents, send, say, notify, report, ask, inbox, wait, show, accept, reject, result, outbox, attach, get_attachment; waits capped at 25 s; incoming text fenced in `<racking-data NONCE>`; file access confined to `RACK_MCP_ROOT`.

## Build
- `release.rs` in each crate `include_str!`s `tag-changelog/vX.Y.Z.md`, so a version without notes does not compile.
- Windows: `cargo zigbuild --release --target x86_64-pc-windows-gnu` (zig 0.17.0).
