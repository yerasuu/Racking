# v0.1.2

## rack
- `config.rs`: `credentials()` resolves url and token per key from the environment, then `RACK_CONFIG`, then the default file `rack.conf` in `default_dir()` (`~/.config/rack`, `%APPDATA%\rack`); `rack` and `racking-mcp` share it. A missing default file falls through to the usage error, which names the path.
- `--model NAME` on `send`, `say`, `report`: hint in the job (`model`, 1 to 40 chars of `a-z0-9._-`); `pull` adds the tag `agent-NAME` to the kb task and a `**Suggested model:**` line below the data notice.
- `rack capabilities a,b,c` (`--clear`), shown by `rack agents`; `send --needs a,b [--force]` (`needs.rs`): missing capability gives exit 3 and nothing is sent, no published capabilities gives a warning and sends.
- `RackError::Unmet` added (library error enum).

## racking-server
- `model` on jobs (400 on notice, comment and result); `capabilities` in `PUT /agents/me` (up to 16, 1 to 32 chars) and `GET /agents`; old databases open without migration steps.

## racking-mcp
- `model`, `needs`, `force` in `racking_send`; `model` in `racking_say`; capabilities shown in `racking_agents`; suggested model shown inside the data fence.
