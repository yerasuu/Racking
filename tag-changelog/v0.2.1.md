# v0.2.1

Fixes only; no protocol or config change.

## racking-server
- `POST /admin/links` answers with `sends {a_to_b, b_to_a}`, computed with `SendRules::may_send` after the link exists, and a `hint` naming the `[permissions] send` entry a refused direction would need (`api/pairing.rs`). A link between two workers still does not grant sending.
- `rate.rs`: the window counter updates through a compare-exchange loop instead of the deprecated `AtomicU64::fetch_update` (builds on newer toolchains with `-D warnings`).
- The pairing test reads the server log after the process exits (it raced a SIGKILL).

## rack
- `rack link --pair A B` prints one `note:` line on stderr per direction that cannot send; nothing extra against a server without `sends`.
- `rack policy`: `Active` keeps `from_role` (older state files load with `None`); the hook's audit lines, `release` included, carry `from` and `from_role`.
