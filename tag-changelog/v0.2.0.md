# v0.2.0

Breaking for servers: the default `allow_from` and the refusal of public binds change what starts and who connects (see "Breaking"). Clients of 0.1.x keep working against a 0.2.0 server that has no roles configured.

## Breaking
- `racking-server`: peers outside `allow_from` (default loopback, private and link-local ranges) get 403 before authentication, `GET /` and `GET /help` included; a `bind` to a public or wildcard address (`0.0.0.0`, `::`) is refused unless `allow_public_bind = true`.
- A task requests a policy profile in the job field `profile`; the first body line `Racking-Profile: NAME` is honoured only for jobs from a server that lacks the field and only from `main`.
- Agents created through the API can send only to agents they are linked with (`agent_links`); agents of the config file stay linked with everyone.
- `racking-server` needs `signal-hook` (Unix); `rust-version` is 1.89.

## racking-server
- Roles: `role = "main" | "worker"` per agent (at most one main), `[permissions] send`, `from_role` set by the server on every job, `403 not_allowed`; no roles configured keeps everyone able to send to everyone and warns at start.
- Limits: `hops` and `parent` (`409 too_deep` above 3), open tasks per sender and recipient (20), jobs per minute (60, `429 rate_limited`), emergency brake `POST /admin/pause` and `/admin/resume` (`503 paused` for workers, `X-Racking-Paused`).
- Admin routes in `api/admin.rs` and `accounts.rs`: create, rotate and remove agents without a restart, tokens stored as sha256, `audit` table and `GET /admin/audit`.
- Pairing: `POST /admin/invites`, `POST /join` (the only route without token besides `GET /` and `GET /help`), pending accounts answer `403 not_confirmed`, four-word fingerprint, confirm or deny, `links` in `agent_links`, `GET /agent-links`, `racking-server invite`.
- Network: `check_peer` before auth, `trusted_proxies` (rightmost untrusted `X-Forwarded-For`, `/0` refused), graceful shutdown on SIGTERM and SIGINT (`shutdown_grace_secs`, default 10, checkpoint of the WAL).
- History: `GET /threads/{id}` (peek, no delivery) and `GET /jobs` search (`LIKE ... ESCAPE`, cursor), index `jobs_reply_to`.
- Broadcast: `to` as a list (up to 16) or `*` for notice, message and report; one job per recipient sharing `group_id`; per-recipient results and `skipped_count`.
- Uploads: resumable chunked uploads (`/jobs/{id}/uploads`, `/uploads/{id}`, `Content-Range`), `max_file_bytes` (2 GiB), `max_job_bytes` (4 GiB), `[quota] per_agent_bytes`, `disk_free_min_bytes` (read with `df -P -k`), `507 insufficient_storage`, `413 over_quota`.
- Job field `profile` (task, main only); `GET /whoami` shows `role`, `paused`, `quota` and limits.

## rack
- `rack link`, `join`, `links`, `unlink`, `admin`, `policy` (init, check, show, decide, hook, release, settings), `thread`, `search`, `listen` (experimental), `watch`, `guide`.
- Say, notify and report accept `a,b,c` or `*`; `send --profile`; `attach` uploads in chunks above 32 MiB, `--resume`, and packs a directory as ustar; `get-attachment --extract` unpacks safely (`--overwrite`, `--max-bytes`, `--max-files`).
- The worker's local policy (`rack::policy`): profiles `workdir`, `app-test`, `compat-launch`, `diagnostics`, anchored `*`/`?` globs, a PreToolUse hook and an audit journal; fails closed.

## racking-mcp
- 19 tools: `racking_thread`, `racking_search`, `racking_guide` and the sender-role and profile lines outside the data fence.

## Deployment
- `Dockerfile`, `compose.yaml` (read-only root, non-root user, `init: true`, `stop_grace_period: 15s`), optional Traefik profile with a file provider and no Docker socket, `deploy/` systemd user unit and `docs/deploy.md`.
